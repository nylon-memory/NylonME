# 概念：空间、记忆库、钥匙

只需要三个词，其余都是管道细节。

```
空间（tenant）   —— 安全边界。一把 key 开一个空间。
  └── 记忆库（owner）—— 空间里的记忆分区。同一库的记忆互相联想，
        库与库之间互不干扰。
        └── 记忆节点
```

## 记忆库（owner）—— 记忆住在哪里

起一个库名然后一直用它：项目 slug（如 `nylonme-project`），或者个人跨项目的
`dev-你的名字`。同一个库 = 记忆互相连接、一起被共振召回；不同的库 = 完全隔离。

库名**不是用户名**，也**不带任何权限**——它就是个文件夹名。持有空间 key 的人
可以读写空间里任何一个库。（真正的「按用户硬隔离」属于应用层职责：你的应用持一把
空间 key，给每个终端用户分配一个库，用户鉴权由你的应用自己做。）

## 空间（tenant）—— 你的 key 开的是哪扇门

每把 key 签发时就绑定了一个空间
（`nylon-engine keys add --tenant <空间> --scope write`）。请求里写别的空间会被
直接拒绝。管理员 key 用 `tenant=*`（通配全部空间）。

小团队共用一台引擎？一个空间（`default`）+ 每人/每项目一个库，就是设计好的用法。
只有当你需要**硬隔离**（比如不同客户、不同部门）时，才给他们各自的空间。

## 钥匙（key）—— 唯一的凭证

没有账号密码。key 就是凭证，档位三选一：`read` / `write` / `admin`。把 key 贴进
控制台顶栏的 key 框，旁边的芯片会立刻回答「我是谁」：开哪个空间、什么档位、成员
别名——背后是 `GET /v1/whoami`。

管理 key 有三个入口，背后是同一份 key 表：

- 服务器 CLI：`nylon-engine keys add / list / revoke`（热加载，不用重启）
- REST：`GET/POST /v1/keys`、`DELETE /v1/keys/{prefix}`（需 admin 档位）
- 控制台 → **Team** 视图（签发 / 吊销 / 成员活动）

## 速查表

| 我想…… | 做法 |
|---|---|
| 不同项目的记忆分开 | 每项目一个库（owner = 项目 slug） |
| 让同事搜到我的项目记忆 | 同空间 + 告诉他库名 |
| 给同事开通访问 | 给他签一把空间的 `write` key |
| 收回权限 | `keys revoke`，热加载立即生效 |
| 硬隔离一个客户/部门 | 单独空间 + 绑定该空间的 key |
| 在上面做多用户应用 | 应用持一把空间 key；每个终端用户一个库；用户鉴权你的应用自己做 |
